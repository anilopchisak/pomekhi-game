# Physical-device acceptance

These scenarios require actual equipment. Mac Chromium/WebKit, loopback and simulated disconnection do not establish Windows, iPhone, Android, cellular-carrier coverage or hotspot compatibility. Record the date, OS/browser versions and observed result when each scenario is performed. They remain unverified until then.

## Redmi Note 8 Pro hotspot

1. Enable the phone's mobile-data hotspot and connect the Windows laptop plus six other phones simultaneously. The sharing phone is the seventh player. Check the hotspot's configured device limit and power-saving settings.
2. Start the built game on the laptop with start-public.cmd. Open the local organizer panel and join the Tuna HTTPS invitation on all seven phones. Verify identical roster, private cards and live timer. Scan the QR with real phone cameras.
3. Start a disposable round. Lock and unlock each phone, visit the intended zones, lose coverage, record own actions, return to base and verify accepted/review receipts without duplicates. Keep the laptop awake and powered. Check captured-group continuation and an individual round withdrawal.
4. After return, keep one phone offline: a new deal and finalization must wait. Reconnect it, resolve conflicts and verify all seven confirmations. Separately exercise explicit close-waiting and a late rejected event.

## Direct local connection

1. Stop the public launcher before starting another server against the same save. Build and run start-lan.cmd. Permit Node on the intended private network through Windows Firewall when prompted.
2. Open the host panel on localhost, choose Local connection, paste the printed laptop IPv4 address and generate the invitation. Open it on the sharing phone and each of the six other phones. Test the actual server URL, not only device Wi-Fi association.
3. With the hotspot still active, disable its mobile data if the phone permits this. All seven open tabs must continue communicating with the laptop. If clients cannot reach each other, this hotspot cannot supply direct LAN mode; use the working Tuna path or a different local network.
4. Disconnect a phone from the hotspot while keeping its game tab open. Record actions and return to coverage. Ordinary HTTP does not provide an offline service-worker reload: test this limit explicitly. Switching from Tuna to LAN uses a different browser origin and does not transfer the private session or queue.

## Native browsers and restart

Run on real Safari/iPhone and Chrome/Android: initial join, private-card conceal/reveal, IndexedDB permission/failure, offline recording of every action, several tabs, a lost acknowledgement, screen lock, tab restoration and background suspension. For HTTPS, wait for confirmed offline preparation before testing airplane-mode reload. For HTTP, retain the open tab.

Restart the Windows server during a disposable search. The organizer must enter the new terminal code; phones retain identities, cards and queued IDs. Play restores paused and resumes only manually. Verify the sound source is reselected and old cues are not replayed. Confirm the QR/clipboard, dim-light readability and battery behavior before the party.

## Ritual rehearsal and balance

With seven real participants, try the tutorial with infection and verify that its successes do not move candles. New finite parties default to seven normal rounds and a 28-step goal. Confirm synchronized results explicitly, read each newly revealed base rule aloud, and exercise one penalty and its correction. A fully captured group ends only its search. Verify victory or final-round defeat, then continue freeplay with the original outcome unchanged.

Record actual successes, penalties and elapsed time including reading and breaks. The 36-minute default timer total includes the tutorial, but is not a party-duration estimate. The mathematical budget and automated perfect-score scenarios do not establish a suitable human win rate; use this rehearsal to assess the initial balance.

## Atmosphere acceptance

On Windows and macOS select one host/broadcast sound source, test phase signals and adjust the speaker in all allowed zones. Verify quiet conversations, clear return/pause cues and comfortable phone effects. On real iPhone/Android explicitly enable phone sound, test silent mode, block/unblock, hide/show and lose/recover connectivity; no skipped effect may replay. Test two tabs and opt-out. Reauthorize after a server restart and verify the global phone-effects switch is off. Fullscreen and an actual television connection are separate hardware checks.
