# First-game lifecycle

The [target rules](../product/README.md) own gameplay intent. This document owns the shared seven-round lifecycle of First Game and Ordinary. Older design descriptions remain references for shared foundations and compatibility fixtures; the executable does not open older round-reset parties.

## Authority and data flow

[Lobby](../../src/server/lobby.ts) owns identity and command authorization. The [game](../../src/server/game.ts) owns phase, locked preparation, confirmed physical status, and the set of people waiting for a later deal. The [dealing owner](../../src/server/dealing.ts) randomizes balanced roles and excludes retained group cards from its eligible pool. Story and offering source text is [server-only](../../src/server/first-game-content.ts). Built-in offerings use internal IDs outside the editable catalog's ID space, so imported entries never replace or lose to a built-in offering with the same ID. The editable catalog's harder flag is independent of historical level metadata.

The [search ledger](../../src/server/search.ts) has a round-local event log seeded with retained groups. Each group has an immutable original assignment identifier and frozen card; it can outlive the original member. New possessed members can report a permitted location during placement. The group carries that location until release. After recall, missing locations can be proposed and confirmed separately; they enter the next round without changing the current round search ledger. Search membership includes both new card recipients and retained members. An exorcist can release several groups in one search event by selecting participant identities. The personal projection lists only infections authored by the current player for independent undo. The next round's rescue denominator counts live original assignments and its mission denominator counts newly dealt exorcists.

The [round inbox](../../src/server/round-sync.ts) replays accepted events and retains decisions, dependencies and receipts. Phones send reports and acknowledge the journal using their personal inbox membership, including when they keep a card from an earlier round. A mission completed before recall can be reported during recall or checking, but always enters explicit review when received after recall. Reports delivered during a pause do not change the ledger. A gameplay report authored on pause is rejected. An organizer decision cannot override eligibility or causal undo. Physical status is recorded separately through the authenticated player's or organizer's command, and must match the current effective result. A network failure never creates a game status. A confirmed group can be kept in play without a connected phone. Unconfirmed free people can be confirmed at a later check.

## Transitions and presentation

Preparation leads to reading, timed placement, timed exorcism, untimed recall, untimed checking, and the next deal or a terminal outcome. A player action cannot advance a timer; timer callbacks and organizer commands share the session queue. Early recall and a normal deadline recall share the free-only return path. Stop closes the pending result without scoring it and recalls everyone.

At finalization the game checks synchronization and physical return availability, carries unresolved groups, and commits the [ritual](../../src/server/ritual.ts) once. Confirmed total possession requires all remaining identities to be confirmed in groups. If some active players are disconnected at recall, the server starts a persisted return wait, normally 90 seconds. At expiry a confirmed online group, a still-disconnected expected player, no confirmed free returner and no unresolved release report permit a terminal no-return result. The timer and journal close commit together. A rescued medium at the base prevents that ending. A penalty has one legal source only when there is one maximum and it is not A. An explicit dismissal is recorded without moving a candle. Revealed prophecy state is independent of the current stack sizes.

The [protocol](../../src/shared/protocol.ts) has distinct organizer and personal projections. The organizer sees named initial roles and check statuses; a phone sees only its own assignment, check status and eligible capture targets. Published candles are committed values. The shared laptop places the timer and settings in its toolbar, with a separate scroll region for reports and history. The phone places its private card in the phase view. Dialog dismissal returns focus to the opener or to the refreshed target list when that opener is disabled. The timer is unknown without a fresh snapshot.

Review dialogs request a versioned server projection of either decision by replaying a detached inbox. They show the new provisional score and changed receipts. Confirmation carries the same game version; changes require a fresh projection. The penalty dialog uses the ritual's projected source, positions and remaining steps from the same calculation that moves the candle. The ritual view plays committed candle steps at 450 ms and shows a reveal for 500 ms. A forward step that empties a stack emits a 300 ms local smoke effect during playback. Reduced motion fades the extinguished candle without rising smoke. Skip, pause and lost connection drop presentation frames and display the committed snapshot.

## Preparation, violation reports and trials

The game chooses a random story once at room creation and saves its identity and text in the existing checkpoint. The room projection carries the selected story. Saving the venue updates the place and categories. Preparation locks after the first deal, including if cancellation returns the room to the lobby. The common Dwelling view identifies the physical place used in private offerings.

New rooms use Ordinary rules and the [server-only authored bank](../../src/server/authored-content.ts). The server checks every selected subset, the number of locations and the enabled contact category. Cards and trials that need a separate venue confirmation are excluded from new parties. The editable bank remains available to the organizer editor and to locked historical rooms that used it. Locked checkpoints retain their settings and private issued text, including historical variants. New draws use the base cards and any enabled comedy missions. An unlocked checkpoint adopts the current setup and preserves any existing story.

The optional comedy setting adds 24 possessed and 16 exorcist missions to the authored draw. The [server-only comedy source](../../src/server/comedy-cards.ts) supplies both the runtime and the offline catalog. Comedy missions have their own IDs and use the ordinary role pools and usage cycles. Venue setup saves the choice and locks it at the first deal. A checkpoint without the setting uses the base draw. Issued comedy assignments restore from the saved text.

The host invitation and reading views reflect the committed phase. The toolbar room code opens the QR invitation in either view. The roster shows public deal status and has a confirmed redeal action next to its heading. The reading controls offer a manual start after a warning if some players are still reading or offline. Composition and pending replacement checks apply to both start paths. The host can replace an assignment from the roster without exposing its private content.

Before the first round, a canceled deal can reopen admission if departures left fewer than five players. Replacements join the same room until the roster has five players. This keeps preparation and the Ordinary trial deck fixed.

Phone violation reports carry the revealed prophecy slot and the player's account. The server exposes a personal reporting capability only when return to the base is confirmed: during checking, or during reading for a confirmed returner who received a new card. The same check guards the command. Authorized review accepts, rejects or dismisses the report without movement for a disputed pile. The decision and its candle change share the session commit. Duplicate commands do not move another candle.

In Ordinary mode the [trial owner](../../src/server/trials.ts) freezes an eligible seven-card deck before dealing and a roster of available targets at the start of exorcism. The affected phone receives the instruction; named witnesses get separate forms with their own facts. Each encounter is scored against the witness from its own slot even when the other slot is blank. In T010 the actor first saves all three traits during exorcism. A second submission adds both witness IDs without changing the traits; it can arrive before the check is sealed. Both steps use the same saved report. Witnesses can append missing facts through checking. Saved values cannot be overwritten. The organizer can exclude or restore evidence at checking and mark individual nonempty T010 answers equivalent to the recorded trait. Exact normalized matches remain automatic.

T001 and T011 list participants without filtering by role on the actor's phone. The server checks the frozen possessed targets at scoring.

T004 permits a late report of the repeat visit only after the server recorded the early return and sent the private reply. The organizer must resolve the pending visit separately before sealing the round. A rejected visit leaves the earlier steps intact. Checkpoints retain pending visits and trait decisions as optional v7 fields. The fixed prophecy branch uses the revealed count on entry to checking. One optional bonus enters the same result and ritual transaction as the search score. Unavailable targets and insufficient evidence close without a bonus or a redraw.

## Storage and checks

The [disk store](../../src/server/session-store.ts) writes schema 7 to data/party-v7.json using the same single-writer lock and atomic commit. Without a v7 file it loads a valid v6 room and preserves the v6 file. A locked v6 room keeps First Game rules. Only the catalog is imported from older saves. An I/O error reading the legacy file opens organizer recovery without writing a default bank. Retry imports the legacy catalog after access is restored. The [validator](../../src/server/session-format.ts) validates and replays the game and inbox before a checkpoint is accepted. Restore keeps a timed phase paused with its saved remainder, and preserves untimed recall and checking.

[Game tests](../../src/server/first-game.test.ts) cover balanced deals, carryover, sole return, loss, scoring, penalties and Pixso candle histories. [Transport and recovery tests](../../tests/integration/persistence.test.ts) use independent real clients and files for delayed review, identity recovery, and repeat finalization. Physical play, live network reachability, audibility, and real mobile devices require the separate [device checks](../testing/device-acceptance.md).
